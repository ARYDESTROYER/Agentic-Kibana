## #2 Cases page severely glitched — fix ASAP

**Root cause:** The `<DataTable sticky>` in Cases.tsx (webui/src/soc/pages/Cases.tsx:1327-1328) renders the header as `<thead className="sticky top-[var(--header-h)] z-10 bg-surface ...">` (ui/table.tsx:57). `--header-h` IS defined (theme.css:146 = 56px), so the "undefined var" hypothesis is NOT the cause — the defined 56px value is precisely what breaks it.

`position: sticky` resolves against the NEAREST ancestor SCROLL container. Between the `<thead>` and the viewport there are TWO overflow boxes that each establish a scroll container yet NEITHER scrolls vertically: (1) DataTable's outer `<div className="overflow-hidden rounded-lg border ...">` (DataTable.tsx:383), and (2) the `<Table>` primitive's wrapper `<div className="relative w-full overflow-auto">` (ui/table.tsx:36). Both size to the table's content height (no max-height), so their vertical scrollTop is always 0. The actual vertical scroller is the WINDOW/document — AppShell root is `min-h-screen` (AppShell.tsx:495), not `h-screen`+overflow, and the app bar is `sticky top-0` on the window.

Because the thead's sticky context is the inner non-scrolling `overflow-auto` wrapper, a positive inset `top: 56px` immediately shifts the header DOWN toward 56px from that wrapper's top edge. The compact header is only `h-9` = 36px tall (table.tsx:121, density=compact) and the first tbody row begins at ~36px, so the opaque header is pushed ~20px+ below its natural slot: it overlaps body rows 1-2 while the top of the first data row peeks ABOVE the header — exactly the screenshot ("a data row cut off above the column header; sticky header not covering; orange left-accent bar reading oddly"). The orange bar is row 1's rowAccent medium-severity band (Cases.tsx:1326) surfacing above the down-shifted header — a symptom, not a separate bug. The sticky can never actually pin under the real app bar here because its scroll container is the local table wrapper, not the window.

Cases.tsx is the ONLY consumer of `<DataTable sticky>` in the whole app (verified: the prop appears only at Cases.tsx:1328), so the defect is fully isolated.

Secondary/minor (not the break): the Status cell uses `flex flex-col` stacking StatusBadge + AutoClosedBadge (Cases.tsx:852-860); AutoClosedBadge self-hides for all non-AI-auto-closed cases (badges.tsx:677), so it only inflates row height on auto-closed rows.

CASES_DEFAULT_HIDDEN is NOT over-hiding: it hides 6 secondary columns (disposition, alerts, playbooks, enrichments, category, urgency) leaving a clean 9-column default (Case ID, Title, Status, Severity, Confidence, Verdict, Risk, Entity, Updated, +Actions when canClose) — verified against the columns array (Cases.tsx:804-1027). Correct as-is.

**Approach:** Remove the sticky header from the Cases table. In a window-scrolled layout with no bounded-height scroll region, a sticky table header CANNOT be made clean without converting the table into a nested inner-scroll container (max-height + inner scrollbar + thead top-0), which changes the scroll model app-wide, adds a second scrollbar, and is NOT what the user asked for (violates "prefer removing clutter over adding"). Removing sticky makes the Cases header render correctly AND behave consistently with every other page's table (all scroll with the document). Subtractive, near-zero-risk: Cases is the sole consumer.

Remove the `sticky` prop from `TableHeader` (ui/table.tsx) making it always `bg-surface/50`, remove the `sticky` pass-through from `DataTable` (DataTable.tsx), and update ui/__tests__/table.test.tsx (drop the sticky-opaque assertion, keep the non-sticky one). ## #5b Auto-reinvestigate when the model API key is (re)provided

**Root cause:** Verified in the real code. When an LLM key is unset, `LLMGateway._provider_kwargs` raises `GatewayError("Anthropic API key not configured" / "OpenAI API key not configured")` (backend/app/llm/gateway.py:124-132). That propagates through `complete()` (records a `UsageOutcome.ERROR` usage row with case_id, then re-raises — gateway.py:189-194). The Router catches it and fails SOFT to UNCERTAIN (router.py:62-64), so the strong investigator always runs next; the investigator's first `complete()` re-raises the same error and is caught at investigator.py:212 → `_fail_to_human(f"investigator model error: {exc}", ...)` → `VerdictResult(verdict=NEEDS_HUMAN, confidence=0.0, recommended_action="investigator model error: ... THE 5 CONSISTENCY RULES (all already implied by §3.1/§3.2 — this just makes them one enforceable checklist):
R1 SECTION RHYTHM — vertical space between major page blocks is ALWAYS `space-y-6`. Never space-y-5, space-y-7, or space-y-8 at page-section level. (space-y-4 stays legal INSIDE a card/panel; space-y-1/2/3 for tight in-component stacks.)
R2 GRID GAP BY TILE TYPE — a strip of KpiTile/StatCard tiles (internal p-4) uses `gap-4`; a grid of full Cards/panels (internal p-6) uses `gap-6`. NEVER gap-5. This encodes the standard's "internal padding ≤ external gap" (§807): 16px tiles → 16px gap, 24px cards → 24px gap. Overview is the exemplar (KPI strip gap-4 at line 884; widget grids gap-6).
R3 ONE HEADER TREATMENT — routed pages use `PageHeader variant="dense"` (plain band, title text-lg/xl). `hero` (card-wrapped) is reserved for onboarding/marketing (Wizard) only. This is the same direction item #7 sets for Overview; extend it to Standup so no operational page has a boxed header.
R4 EVERY ROUTED PAGE HAS A WIDTH ARCHETYPE — wrap the body in <PageContainer>: operational/dashboard/table pages `variant="wide"`, forms/admin/settings `variant="fixed"`, narrative `variant="prose"`, dashboard canvas `variant="fluid"`. No page renders un-capped.
R5 ONE EYEBROW SIZE PER ROLE — the uppercase overline is `text-2xs font-semibold uppercase tracking-wide text-muted-foreground` (prefer the existing <Eyebrow> primitive); the 12px section-kicker keeps `text-xs`. Raw text-[10px]/[11px]/[0.6rem]/[0.65rem] eyebrows all collapse to the token. No arbitrary text-[..] sizes for labels.

For each edit: swap gap-5→gap-6 (card/panel grids) or gap-4 (tile strips — decide per grid by what it holds); space-y-5/space-y-8→space-y-6 at section level; wrap the 4 pages in PageContainer; change Standup hero→dense; token-swap the raw eyebrow sizes. Keep the diff mechanical and reviewable.
