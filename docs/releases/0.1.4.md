# Agentic SOC 0.1.4 failed publication

Agentic SOC **0.1.4** reached the accepted `main` source tree and received the
immutable annotated tag `v0.1.4` on 5 August 2026. Its complete application CI,
exact-tag CI, documentation build, and GitHub Pages deployment passed. The signed
release workflow then stopped before building any release artifact.

!!! danger "Not an installable Stable release"

    `v0.1.4` has no published GitHub Release, GHCR release images, immutable image
    digests, image signatures, `upgrade-plan.json`, or Sigstore plan bundle. Do not
    bootstrap, install, or relabel a deployment from this tag. `v0.1.1` remains the
    last verified installable Stable release until a corrected newer publication
    completes. The subsequent immutable `v0.1.5` attempt also failed before its
    canonical plan and GitHub Release. Version 0.1.6 published signed artifacts but
    failed canonical macOS Bash 3.2 bootstrap acceptance. Version 0.1.7 published
    and fixed that host-script defect but exposed a later updater control-socket
    startup failure. Version 0.1.8 corrected that boundary but remained
    bootstrap-blocked when cosign used an unwritable TUF cache beneath the read-only
    root filesystem. Version 0.1.9 corrected that trust-root path but failed later
    in its constrained verification fixture. Version 0.1.10 then timed out during
    the emulated Web Console build; the current corrected candidate is 0.1.11.

## What succeeded

- The accepted 0.1.4 source was promoted through the protected Testing-to-main path.
- The exact `v0.1.4` tag CI run passed every independent lane and the fail-closed
  **CI passed** aggregate.
- The version-matched 0.1 Help Center built and its immutable-tag documentation
  deployment succeeded.
- No updater trust, signing, image, migration, or deterministic-decision boundary
  was bypassed.

## What failed

The release publisher's draft-inventory step correctly classified the initial remote
state as:

```json
{
  "release_state": "absent",
  "release_exists": false,
  "plan_exists": false,
  "bundle_exists": false
}
```

The workflow extracted the valid boolean fields with `jq -e`. By definition, `jq -e`
returns exit status 1 when its result is the JSON value `false`, so `set -e` stopped
the job even though the classifier had reported the expected empty starting state.
The failure occurred before QEMU/buildx setup, image publication, signing, plan
generation, or GitHub Release creation. There is no partial release state to resume.

## Immutable disposition

The tag is historical evidence and must never be deleted, moved, force-updated, or
reused. Because the repair changes release code referenced by the tag, the old
workflow cannot be repaired by rerunning `v0.1.4`; release discipline requires a new
patch version.

The current corrected candidate is [Agentic SOC 0.1.11](0.1.11.md). It carries the
exact accepted 0.1.4 application scope, fixes boolean extraction without weakening
the classifier, preserves every later immutable publication record, and repeats the
complete Testing, promotion, main, tag, signing, anonymous-pull,
canonical-bootstrap, and browser gates.

## Operator action

- Do not use `git switch --detach v0.1.4` as an update bootstrap.
- Do not expect `/releases/download/v0.1.4/upgrade-plan.json` or a 0.1.4 GHCR image
  to exist.
- Keep an existing canonical `v0.1.1` deployment unchanged until `v0.1.11` is fully
  published and independently verified.
- Reconcile Testing/source-built 0.1.3 or 0.1.4 deployments manually; neither is an
  immutable signed Stable installation source.
