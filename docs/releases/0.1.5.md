# Agentic SOC 0.1.5

Agentic SOC **0.1.5** is an immutable, **non-installable publication attempt**.
Its source carried the accepted 0.1.4 application scope, repaired that attempt's
release-inventory parser, and tightened shipping-image dependency checks. The
`v0.1.5` workflow built and signed candidate component digests, but stopped in its
anonymous multi-platform pull gate before publishing the canonical signed plan,
Sigstore plan bundle, GitHub Release, or Stable convenience tags.

Those partial registry objects are not installation authority. The corrected release
is [0.1.6](0.1.6.md); `v0.1.5` must never be moved, deleted, recreated, or reused.

!!! danger "Do not install, bootstrap, or update from v0.1.5"

    The annotated tag exists, but the complete release evidence does not. There is no
    canonical public GitHub Release containing `upgrade-plan.json` and
    `upgrade-plan.sigstore.json`, so the supervisor has no authenticated 0.1.5 plan
    to consume. Candidate tags and signed image digests created by the failed workflow
    are inert and must not be copied into an override manually.

## What the attempt contained

The source tree recorded by `v0.1.5` included:

- the accepted Security Command Center, Case Manager, Workspace Chat, runbook,
  playbook, Intelligence, approval, export, and installed Help Center scope;
- OpenAI live Flex preference with truthful Standard fallback and one usage ledger;
- a reviewed `wheel` version compatible with the backend runtime's constrained
  `packaging` dependency;
- `pip check` inside both backend image build stages and the final image CI gate; and
- a corrected release-inventory parser that treats valid JSON `false` values as data.

## Exact failure boundary

The release workflow successfully:

1. verified the immutable annotated tag and exact accepted `main` commit;
2. required the exact successful tag CI aggregate;
3. built public multi-architecture candidate images for backend, Console, and updater;
4. resolved their immutable index digests; and
5. signed and verified each digest with the exact tagged release-workflow identity.

Publication then stopped while proving anonymous Docker pulls. The gate pulled
`linux/amd64` and `linux/arm64` through the same index-digest reference in one classic
Docker image store. Docker retained the first selected platform under that reference
and rejected the second, even though the remote index and both child manifests were
valid and public.

Because the workflow stopped there, version 0.1.5 has **none** of the canonical
installable release objects:

- no public GitHub Release;
- no canonical `upgrade-plan.json`;
- no canonical `upgrade-plan.sigstore.json`;
- no Stable `backend:v0.1.5`, `webui:v0.1.5`, or `updater:v0.1.5` convenience tag;
- no canonical bootstrap receipt; and
- no enabled in-app update path.

The candidate image digests and their Sigstore attachments are forensic evidence of
the failed run only. They cannot substitute for the absent signed plan and published
Release.

## Why the tag cannot be repaired

The release job executes the workflow stored in the immutable tag commit. A later
workflow correction cannot change that source by rerunning `v0.1.5`. Moving the tag
would destroy its audit identity, while deleting and recreating it would violate the
release contract.

The only valid recovery is a strictly newer patch release that repeats every gate.
Version 0.1.6 preserves the tag, corrects the anonymous pull verifier, rebuilds and
signs new component digests, generates and signs a new plan, publishes a new GitHub
Release, and exercises the canonical supervised bootstrap independently.

## Operator action

Do not run bootstrap, artifact-download, image-pin, or tag-creation commands from this
historical page. Use the [0.1.6 release procedure](0.1.6.md) only after all evidence it
requires is present, or continue using a previously verified Stable release.

For the general immutable promotion and recovery policy, read
[Release channels and versioning](channels.md). For the supported supervisor boundary,
read [Upgrades and promotion](../operations/upgrades.md) and
