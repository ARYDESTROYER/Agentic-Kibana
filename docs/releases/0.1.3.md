# Agentic SOC 0.1.3

Agentic SOC **0.1.3** was a backward-compatible beta candidate in the **0.1**
documentation line. Its accepted source reached Testing/main, but no immutable
annotated `v0.1.3` tag, GitHub Release, signed upgrade plan, or supported Stable image
set was published. It remains here only as a historical Testing record.

!!! danger "Unpublished snapshot — do not deploy or tag"

    There is no official `v0.1.3` release artifact or updater source. Do not create
    that tag retroactively, relabel a source build as Stable, or execute old tag and
    bootstrap commands copied from an earlier draft. The governed successor is
    [Agentic SOC 0.1.5](0.1.5.md).

## Snapshot highlights

The 0.1.3 candidate added or hardened:

- the isolated supervised-update implementation for the reference single-replica
  PostgreSQL Compose topology, including signed-plan verification, digest-pinned
  application images, verified backup, durable progress, and image rollback;
- cloud-IAM compromise and data-exfiltration runbooks, exact-match response
  playbooks, and dedicated cloud-identity and data-protection personas;
- truthful detection-rule authoring, evidence states, collaboration degradation,
  Standup degradation, responsive Rules and Case Manager layouts, and shared empty
  states; and
- stricter release acceptance, immutable action and Docker-base references,
  fail-closed workflow policy, separate deployment/updater checks, real reference
  PostgreSQL readiness, and shipping-image builds.

These capabilities are included in the 0.1.5 release candidate together with the
actual Stable publication artifacts. See the [0.1.5 release record](0.1.5.md) and
[changelog](https://github.com/ARYDESTROYER/Agentic-Kibana/blob/main/CHANGELOG.md)
for the complete promoted scope.

## Why this is not Stable

SemVer and channel provenance are separate. A package or source tree can report
`0.1.3` while remaining Testing. Stable identity additionally requires:

- the exact accepted `main` commit;
- an immutable annotated tag with matching version;
- successful fail-closed CI on Testing, main, and that tag;
- public digest-pinned backend, Console, and updater images;
- image signatures tied to the exact tagged release workflow identity;
- a signed canonical upgrade plan and Sigstore bundle; and
- an immutable GitHub Release containing the verified canonical asset inventory.

None of those publication artifacts exists for 0.1.3. The last Stable release before
0.1.5 is `v0.1.1`.

## Historical boundary

Version 0.1.3 must never be used as an operational bootstrap identity or newly
published tag. A mutable/source-built 0.1.3 deployment must follow the current
[upgrade procedure](../operations/upgrades.md) to enter the canonical signed Stable
line. If a post-publication correction is needed after `v0.1.5`, prepare a new patch;
never repair history by creating or moving `v0.1.3`.

For current compatibility, rollback limits, exact artifacts, verification commands,
and immutable-tag procedure, use [Agentic SOC 0.1.5](0.1.5.md),
[Known limitations](known-limitations.md), and
[Release channels and versioning](channels.md).
