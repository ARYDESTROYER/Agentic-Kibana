# Agentic SOC 0.1.9

Agentic SOC **0.1.9** is the governed Sigstore trust-root portability correction
after the immutable `v0.1.8` publication. Version 0.1.8 completed exact-tag CI,
public multi-platform images, image and plan signing, the canonical plan and bundle,
the GitHub Release, and the versioned Help Center. Canonical PostgreSQL Compose
bootstrap then reached signed-plan verification inside the read-only updater
container and found that cosign 3 defaults its TUF cache to `/root/.sigstore`.
Because the supervisor intentionally has a read-only root filesystem, cosign could
not initialize that path and bootstrap stopped before application switching.

Version 0.1.9 moves only that trust state to the existing writable updater-state
volume and makes bootstrap replace an inspectable idle supervisor whose reported
version does not match the target. It does **not** change the application-state
schema, updater protocol 1, keyless publisher identity, process UID/GID, Linux
capability set, trust policy, signed-plan schema, or frozen base Compose file. It
remains in the **0.1** documentation line.

!!! warning "Verify the immutable release before installation"

    A source checkout, branch head, version string, candidate image, or signed image
    alone is not a Stable release. Version 0.1.9 is installable only when the
    annotated tag `v0.1.9` resolves to the accepted `main` commit, exact-tag CI and
    release workflows succeed, the GitHub Release contains the canonical signed plan
    and bundle, every digest in that plan is anonymously readable, and the canonical
    bootstrap/update acceptance completes. If any evidence is absent, continue
    using a previously verified Stable release.

    The immutable `v0.1.8` tag, public images, signatures, plan, bundle, GitHub
    Release, and Help Center remain factual publication evidence and must never be
    moved or replaced. Its canonical bootstrap is unsupported because cosign cannot
    initialize its default TUF cache on the read-only root filesystem. Use `v0.1.9`
    only after every acceptance gate on this page succeeds.

## What changed after 0.1.8

The updater image now bakes this environment contract:

```text
TUF_ROOT=/var/lib/agentic-soc-updater/sigstore-root
```

`/var/lib/agentic-soc-updater` is the existing writable, host-persistent updater
state volume. Cosign can initialize and reuse its TUF trust metadata there while the
container root filesystem remains read-only. This is a runtime-path correction, not
a change to the certificate identity, OIDC issuer, repository binding, signed plan,
or image-signature verification rules.

Bootstrap now compares the idle supervisor's reported updater version with the
exact target release in addition to checking protocol, required capabilities, ready
state, and absence of an active job. A healthy 0.1.8 supervisor left by the failed
bootstrap is therefore replaced with the exact 0.1.9 updater before signed-plan
verification. Compatible protocol alone is no longer enough to reuse a mismatched
idle image. Active, unreadable, malformed, or otherwise unsafe supervisor state
continues to fail closed.

Shipping-image acceptance verifies that the baked TUF root points to the writable
state volume. Stable publication also starts the real digest-pinned updater with the
production `read-only`, `cap_drop: ALL`, and `no-new-privileges` constraints, then
runs `cosign verify-blob` for the canonical signed plan inside that container before
the GitHub Release becomes public.

The updater remains the only component with host-runtime authority. It continues to
run as UID/GID `0:10001` with all Linux capabilities dropped. The ordinary backend
and browser still never receive the Docker socket, registry credentials, host
commands, arbitrary artifact coordinates, or migration authority.

No application-state schema migration is introduced. The frozen base Compose SHA is
unchanged, and all application pins remain in the signed generated override.

## Compatibility and migration

The supervised path supports only the canonical, single-replica standalone Compose
deployment with PostgreSQL-owned application state, canonical service/container/
network names, the canonical PostgreSQL volume, durable secrets,
`TLSOC_AUTH_ENABLED=true`, and updater protocol 1.

The frozen `deploy/docker-compose.agnostic.yml` SHA-256 remains:

```text
e3f7ecbb0f749cc9d88f4392c58c9a63ddbd064e80ecde9f21fe9de199086fd4
```

Release-specific version and digest pins exist only in the signed generated
override. Changing that base requires a new protocol and manual bootstrap; it must
never be hidden inside a patch plan.

SQLite, Elasticsearch-owned state, external PostgreSQL, Kubernetes, the legacy ELK
merge, horizontal replicas, modified Compose topology, missing durable secrets, or
unsupported migrations remain **Manual upgrade required**. PostgreSQL and Redis
infrastructure remain operator-managed.

There is no application-state schema migration in 0.1.9. A catalog-verified
PostgreSQL dump is still mandatory before application switching. Automatic rollback
restores prior application image pins; database restore remains an explicit
break-glass operation because restoring automatically could discard valid writes.

## Bootstrap and upgrade boundary

For a canonical deployment currently running supported Stable `v0.1.1`, use a
clean checkout of the strictly newer, fully published `v0.1.9` tag as the
host-authorized bootstrap transport:

```bash
git fetch --tags origin
git switch --detach v0.1.9
test "$(git cat-file -t v0.1.9)" = tag
test "$(git rev-parse 'v0.1.9^{commit}')" = "$(git rev-parse HEAD)"
test -z "$(git status --porcelain --untracked-files=all)"

# .env must contain durable TLSOC_PG_PASSWORD, TLSOC_AUTH_ENABLED=true,
# TLSOC_AUTH_JWT_SECRET with at least 32 characters, and:
# AGENTIC_SOC_UPDATE_REPOSITORY=ARYDESTROYER/Agentic-Kibana
./scripts/bootstrap-updater.sh
```

The bootstrap verifies the exact release before installing or reconciling the
private supervisor and applying its strictly newer plan. If a failed 0.1.8 attempt
left an inspectable idle 0.1.8 supervisor while the application stayed on v0.1.1,
the 0.1.9 bootstrap preserves durable state and replaces that mismatched supervisor
before signature verification. It never reuses the old image merely because it
reports protocol 1. Active, unreadable, or invalid supervisor state still fails
closed and requires documented recovery.

After the successful transition, use `./scripts/agentic-soc-compose.sh` for every
manual lifecycle operation so the active digest override and lifecycle lock remain
in effect.

Source-built/Testing deployments and the immutable 0.1.4 through 0.1.8 failed or
bootstrap-blocked publication records cannot be relabeled Stable. Reconcile them
only through the documented 0.1.9 path appropriate to their actual installed state.
The updater deliberately requires a strictly newer target, so a deployment already
running 0.1.9 cannot bootstrap from the 0.1.9 plan.

Read [Upgrades and promotion](../operations/upgrades.md) and
[Known limitations](known-limitations.md) before rehearsing the transition.

## Independent artifact verification

Verify that the remote exposes both the annotated tag object and its dereferenced
commit before inspecting release assets:

```bash
git ls-remote --tags https://github.com/ARYDESTROYER/Agentic-Kibana.git \
  refs/tags/v0.1.9 'refs/tags/v0.1.9^{}'
```

The command must return two different 40-character object IDs: the annotated tag
object and the accepted `main` commit to which it dereferences.

Install a reviewed cosign version and verify the release plan:

```bash
tag=v0.1.9
repo=ARYDESTROYER/Agentic-Kibana
identity="https://github.com/${repo}/.github/workflows/release.yml@refs/tags/${tag}"
base="https://github.com/${repo}/releases/download/${tag}"

curl --fail --location --output upgrade-plan.json "${base}/upgrade-plan.json"
curl --fail --location --output upgrade-plan.sigstore.json \
  "${base}/upgrade-plan.sigstore.json"

cosign verify-blob \
  --bundle upgrade-plan.sigstore.json \
  --certificate-identity "${identity}" \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  upgrade-plan.json
```

Verify all three immutable digest references with a fresh Docker configuration so
cached credentials cannot satisfy the public-access test:

```bash
anonymous_docker_config="$(mktemp -d)"
for component in backend webui updater; do
  image="$(jq -er --arg component "${component}" \
    '.components[$component].image' upgrade-plan.json)"
  cosign verify \
    --certificate-identity "${identity}" \
    --certificate-oidc-issuer https://token.actions.githubusercontent.com \
    "${image}"
  DOCKER_CONFIG="${anonymous_docker_config}" docker buildx imagetools inspect \
    "${image}" >/dev/null
done
```

The release workflow additionally performs credential-free HTTP reads of each exact
index, child manifest, and config. Repository administrators must make the three
GHCR packages **Public** if anonymous reads return 401; package visibility is a
GitHub setting and cannot be established by image push alone.

## Release acceptance

Publication requires the fail-closed `CI passed` aggregate on the frozen 0.1.9
candidate on `Testing`, the resulting content-equivalent `main` commit, and the exact
immutable `v0.1.9` tag. The release workflow then requires:

1. the annotated tag and its dereferenced commit equal the accepted `main` SHA;
2. all three dual-platform images build, carry exact Stable labels, and are signed;
3. every image digest is anonymously readable and content-verified;
4. the canonical plan passes schema, compatibility, digest, and Sigstore checks;
5. the real digest-pinned updater verifies that signed plan under the constrained
   production runtime, with its baked TUF root writable on the state volume;
6. the private draft contains exactly the canonical notes, plan, and bundle; and
7. downloaded release assets byte-match before the draft becomes public.

The candidate must also pass the Console browser matrix and canonical PostgreSQL
Compose bootstrap/update rehearsal. The end-to-end rehearsal must replace an idle
mismatched 0.1.8 supervisor, apply the signed 0.1.9 plan, retain a durable receipt and
verified backup, and activate an exact coherent backend/Console pair. Never move,
reuse, or repair a published tag. Any later defect receives a newer SemVer.

## Exact Stable build identity

Resolve every Stable stamp from the exact annotated tag on the accepted `main`
commit. Never substitute a branch head, local clock, or unknown value:

```bash
git switch main
git pull --ff-only origin main
git fetch --tags origin

release_version="$(tr -d '[:space:]' < VERSION)"
test "${release_version}" = "0.1.9"
release_sha="$(git rev-parse "v${release_version}^{commit}")"
test "${release_sha}" = "$(git rev-parse HEAD)"
release_date="$(git show -s --format=%cI "${release_sha}")"

export TLSOC_VERSION="${release_version}"
export TLSOC_RELEASE_CHANNEL=stable
export TLSOC_BUILD_SHA="${release_sha}"
export TLSOC_BUILD_DATE="${release_date}"
```

Backend, Console, updater, `/release.json`, OCI labels, signed plan, tag, and GitHub
Release must all resolve to the same version and commit. A mismatch fails safe to
Testing and cannot authorize installation.

## Immutable annotated-tag checklist

Create the tag only after the clean candidate passes on `Testing`, promotion passes
on the resulting `main` commit, and the final tree is frozen:

```bash
test "$(tr -d '[:space:]' < VERSION)" = "0.1.9"
test -z "$(git status --porcelain)"
git tag -a v0.1.9 \
  -m "Agentic SOC 0.1.9" \
  -m "Stable updater Sigstore trust-root portability correction: writable TUF state, exact idle-supervisor replacement, and constrained signed-plan acceptance. Detailed notes: docs/releases/0.1.9.md; CHANGELOG.md."
test "$(git cat-file -t v0.1.9)" = tag
test "$(git rev-parse 'v0.1.9^{commit}')" = "$(git rev-parse HEAD)"
git show --no-patch --show-signature v0.1.9
git push origin v0.1.9
```

Do not create the tag before all candidate/main gates pass, and never force, delete,
move, or reassign it after push. See [Release channels and
versioning](channels.md) for the canonical promotion sequence.
