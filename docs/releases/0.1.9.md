# Agentic SOC 0.1.9

Agentic SOC **0.1.9** is an immutable, **non-installable failed-publication
record**. Its exact annotated tag and partial registry objects remain useful audit
evidence, but there is no 0.1.9 GitHub Release, no published signed-plan asset pair,
no Stable convenience tags, and no supported 0.1.9 bootstrap path.

!!! danger "Historical evidence only — never install from this tag"

    Do not run `scripts/bootstrap-updater.sh` from `v0.1.9`, construct an update
    plan from this page, manually pin its image digests, or create, move, delete,
    recreate, or force-update the tag. The active independently gated procedure is
    [Agentic SOC 0.1.11](0.1.11.md). Version 0.1.10 is also an immutable,
    non-installable failed-publication record.

    A signed image or generated signed plan alone is not installation authority.
    The required GitHub Release and exact two-asset inventory were never published.

## Intended correction

Version 0.1.8 had published its signed images, canonical plan and bundle, GitHub
Release, and Help Center. Canonical PostgreSQL Compose bootstrap then reached
signed-plan verification in the read-only updater and stopped before application
mutation because cosign 3 tried to initialize its default TUF cache under the
unwritable `/root/.sigstore` path.

The immutable 0.1.9 source corrected that defect by baking:

```text
TUF_ROOT=/var/lib/agentic-soc-updater/sigstore-root
```

That directory resides on the existing writable updater-state volume. Bootstrap
also learned to replace an inspectable idle supervisor whose exact updater version
did not match the target release. These remain valid historical source changes and
were carried through 0.1.10 and remain in 0.1.11. They changed no application-state schema, updater
protocol, signed-plan schema, keyless publisher identity, process UID/GID,
capability set, or frozen base Compose bytes.

## Exact failure boundary

The next gate started the real digest-pinned updater with the production
`read_only`, `cap_drop: ALL`, and `no-new-privileges` constraints and mounted the
generated plan and bundle at `/verification`. The GitHub-hosted runner had created
the bind source with `mktemp -d`, whose directory mode was `0700`. Once every Linux
capability was dropped, even the container's UID 0 process could not traverse that
runner-owned directory. The supervisor stopped with:

```text
Error: open /verification/upgrade-plan.json: permission denied
```

This was a release-test fixture portability defect, not a plan-signature failure,
application migration, updater state-machine failure, or attempted workload switch.
No application container, database, or active release override was changed.

Because this mandatory gate failed, the workflow skipped:

- successful completion of constrained-supervisor plan verification;
- SBOM/provenance attestation publication;
- the public GitHub Release;
- publication of `upgrade-plan.json` and `upgrade-plan.sigstore.json` as Release
  assets;
- Stable image convenience tags; and
- versioned Stable Help Center publication.

Documentation run `30990209189` therefore failed closed during Stable assembly: it
correctly found no signed public GitHub Release from which to establish the Stable
documentation identity.
