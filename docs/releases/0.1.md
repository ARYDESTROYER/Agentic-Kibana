# Agentic SOC 0.1

Agentic SOC 0.1 is the first standardized application and documentation release line.
Human-facing documentation uses **0.1**; packages, APIs, and images use Semantic
Version **0.1.0**. After Stable promotion, the immutable release tag is
**`v0.1.0`**.

Builds on `Testing` are integration and acceptance builds. A build becomes the
supported Stable release only when that accepted source tree is promoted to `main`,
the resulting commit passes the release gate, and it is tagged `v0.1.0`.

The repository currently has `Testing` and legacy/default `claude/main`, but no
literal `main` or `v0.1.0` release tag. Version 0.1 is therefore still a Testing
candidate. Provisioning and protecting the Stable branch is a publication
prerequisite, not a naming shortcut.

## What 0.1 provides

- Vendor-neutral pull and push ingestion normalized to OCSF.
- Elasticsearch, OpenSearch, and Wazuh pull connectors plus a broad receiver catalog.
- Durable cursors, deterministic correlation/risk scoring, and source-scoped case
  identity.
- Tiered model investigation through one cost-ledger gateway.
- Deterministic close/escalate policy that the model, a playbook, or notification
  cannot override.
- A Security Command Center with selected-window lifecycle KPIs, active risk,
  open/resolved composition, latest-case hover details, noise reduction, response
  timing, and deeper analytics. It defaults to visibility-aware five-second LIVE
  refresh and can expand Noise Reduction without exposing raw alert IDs.
- Cases, traces, rationale, collaboration, feedback, campaigns, baselines, tuning,
  rules, and custom dashboards. **Case Manager** provides a persisted, accessible
  resizable split-pane active/all queue, a six-tab canonical detail workspace,
  redacted alert → cluster → case explanation, and permission-gated bulk operations.
  The **Cases** table remains available during migration and hands exact record links
  into Case Manager.
- A standardized command-center Console grammar with a searchable flat Settings
  frame, persisted System/Light/Dark appearance, route-aware loading feedback, a
  bottom Documentation destination, and the targeted **Entity investigation**
  workflow. Documentation opens the version-matched Help Center bundled with the app;
  GitHub is a secondary source/edit destination. The redundant Automated Scans screen
  remains deep-link compatible but is removed from primary navigation.
- A browse/open/create/edit Playbooks manager for operator-authored Markdown;
  bundled procedures remain protected and every mutation is permission-gated,
  atomically reloaded, and audited.
- PostgreSQL/pgvector, Elasticsearch, or SQLite application-state backends.
- Local authentication, sessions, RBAC/custom roles, TOTP MFA, and OIDC SSO.
- Provider-aware notifications, knowledge retrieval, enrichment, and spend controls.
- Compatible official OpenAI alert/case calls prefer live Flex with truthful standard
  fallback by default; the independent asynchronous Batch queue remains opt-in.
- An isolated five-source Demo Mode (Splunk, QRadar, Wazuh, syslog, and Microsoft
  Entra ID / Active Directory) and a bounded, audited, secret-free portable
  application-state export for authorized administrators.
- A standalone React web console and version-matched Help Center served from the same
  application origin, with a complementary versioned public Stable site.

## Safe defaults and explicit choices

The balanced autopilot profile performs broad deterministic ingest/routing and enables
a $10/day blocking LLM budget backstop. A blocked provider call routes work to human
review rather than silently discarding it. `NEEDS_HUMAN` never auto-closes, and
true-positive auto-close remains an explicit opt-in.

Authentication is off in the base configuration for isolated evaluation compatibility.
Operators must enable authentication, replace demonstration credentials, configure
HTTPS/secure cookies, and apply least privilege before shared use.

## Recommended deployment

Use the standalone Compose stack with PostgreSQL/pgvector for application state and
Redis for caching. Connect source systems through scoped connector credentials. Existing
Elasticsearch environments may instead hold Agentic SOC state in dedicated indices, using
separate management and read-only log credentials.

Record the exact tag, image digests, commit SHA, build date, state backend, and
`/api/health/build-info` response. A branch name alone is not a release identity.
The Console badge shows `v0.1.0 · Testing|Stable` and exposes both Console and
backend stamps; any identity mismatch is visibly downgraded to Testing.

## Important limitations

Version 0.1 does not claim:

- high availability or horizontally coordinated workers;
- a complete database migration/rollback framework;
- an integrated durable secret manager;
- durable pre-ack receipt semantics for every push transport;
- multi-tenant row-level isolation by default;
- production certification for every source/vendor combination;
- that Agentic SOC ledger estimates equal provider invoices;
- autonomous write-side response actions.

Use synthetic or non-sensitive data until the selected deployment, source protocol,
model provider, backup, and failure behavior have been validated. Read the full
[Known limitations](known-limitations.md).

## Upgrade and support boundary

Back up the state store and deployment secrets before changing versions. Because 0.1
lacks a complete schema-migration framework, do not assume that starting an older image
is a safe rollback; restore the matching pre-upgrade state when compatibility is not
explicitly documented.
