# Agentic SOC 0.1.10

Agentic SOC **0.1.10** is an immutable, **non-installable failed-publication
record**. Its annotated tag passed the governed source and exact-tag CI gates, but
the signed-release workflow reached its fail-closed 120-minute job timeout while
building the multi-platform Web Console image. There is no public 0.1.10 GitHub
Release, no canonical signed-plan asset pair, no complete signed three-image set,
no Stable convenience-tag set, and no supported 0.1.10 bootstrap or update path.

!!! danger "Historical evidence only — never install from this tag"

    Do not run `scripts/bootstrap-updater.sh` from `v0.1.10`, construct a plan from
    this page, manually pin a candidate image, or create, move, delete, recreate, or
    force-update the tag. Version 0.1.11 is also an immutable non-installable
    failed-publication record. The separately governed correction is [Agentic SOC
    0.1.12](0.1.12.md), and it is installable only after its own complete
    signed-publication and canonical acceptance sequence passes.

    A green source CI run, annotated tag, candidate image, or source version is not
    installation authority. The required exact public Release and its two signed
    plan assets were never published for 0.1.10.

## Intended correction carried forward

The immutable 0.1.9 attempt had failed before publication because its real
capability-dropped supervisor could not traverse the runner-owned verification
directory. Version 0.1.10 corrected that fixture without widening the updater:

1. install `upgrade-plan.json` and `upgrade-plan.sigstore.json` with mode `0444`;
2. make their temporary directory read-only and traversable with mode `0555`; and
3. mount that directory read-only at `/verification` before invoking the shipping
   updater.

The release-policy gate locks that exact least-privilege ordering and rejects broad
permission changes, ownership changes, source `cp`, runtime entrypoint overrides,
or privilege expansion. The writable Sigstore trust state remains on the existing
updater-state volume:

```text
TUF_ROOT=/var/lib/agentic-soc-updater/sigstore-root
```

These source corrections remain valid and are carried forward by 0.1.12. They
changed no application-state schema, updater protocol, signed-plan schema, keyless
publisher identity, process UID/GID, capability set, or frozen base Compose bytes.

## What the immutable workflow proved

The `v0.1.10` candidate passed its required pull-request, `Testing`, promotion,
`main`, and exact-tag CI aggregates. The annotated tag resolves to the accepted
`main` commit. Signed-release run `30997996274` then:

- validated the exact immutable tag, version, accepted commit, and prior CI result;
- built and published the backend candidate image; and
- began the dual-platform Web Console image build.

The architecture-independent Python documentation and Node application builder
stages had not declared BuildKit's native build platform. During the arm64 target,
`npm ci` therefore ran through target-architecture emulation on the amd64-hosted
runner. That step remained active until the release job reached its 120-minute
timeout. The workflow failed closed before any deployment mutation.

## Exact failure boundary

The workflow stopped in **Build and publish Web Console by immutable digest**. It
did not complete or publish:

- the Web Console or updater candidate digests;
- the complete three-image signature set;
- the canonical `upgrade-plan.json` and Sigstore bundle;
- constrained-supervisor plan verification;
- SBOM/provenance attestations;
- the GitHub Release and its exact two-asset inventory;
- Stable image convenience tags; or
- Stable Help Center publication.

The documentation workflow correctly failed closed while waiting for the absent
exact signed Release. No application switch, state migration, or updater job began.
